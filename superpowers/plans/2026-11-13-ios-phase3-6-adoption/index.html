    Global constraints (in addition to the iOS plan's)

    • Mixed versions. Read GET /config features: alerts_api (2), price_alerts_v2, live_prices, sharing (0/1), notifications_api, notifications_v2, apns, social, play (0/1), game. Never call a route whose flag is absent or 0; the older backend gets today's screens, silently, no retry storm. Unknown JSON keys, notification kinds and categories, advice codes and share kinds are ignored (an unknown share kind is a plain link). /config is cached 5 min server-side, so a 404 from a flagged route degrades that feature off for the session.
    • Server decides. The app never recomputes verdicts, advice codes, savings, scores or quiz points and never calls SerpAPI or any price source. Exception: the quiet-hours evaluator used for on-device notifications (R10), tested against the golden file.
    • Wording. "Caught a drop of $X", never "saved". Every price shows its age (checked_days_ago); checks_paused says live checks are paused, never "great price now"; an estimate is labelled "estimate" and never counts. No currency conversion: total_usd plus by_currency lines.
    • hide_game (features.game false or the account setting) hides XP, badges, levels, boards, Play and all game wording, in notifications too. An unreadable setting counts as hidden for game wording.
    • Credentials do not exist (SerpAPI, APNs, FCM, SMTP, Meta). Everything is config-gated and inert; tests use fakes (MockURLProtocol, Fake*Repository, FakeNotificationCenter, FakeClock, FakeShareCardLoader, FakeLocationProvider, a fake APNs payload). No test reaches a real network.
    • Strings in all 7 languages (en es de fr hi zh bn). Web namespaces on main already cover most copy (priceStory, dropMoment, savings, quickWatch, watchSuggest, alertPrefs, alertsHub, share, notifications, social, play, socialShare, playYou, game; adminSocial is out of scope). Only mobile-only keys that no web namespace has go into the web mobile namespace in all 7 languages (Task 0a, dropped if nothing is missing), then scripts/upstream/sync.sh re-vendors. i18n/pending/en stays empty. Server error codes are translated; the backend detail is the fallback. Missing key falls back to English, never the raw key. User-facing text only through L10n.
    • Telemetry only events in the vendored registry, platform: "ios", enum/bool/int props, no PII, no handles, ids, tokens, share URLs, free text or location; every control gets a tid through the Task 13 modifier; calls are synchronous and non-throwing for the caller. Events: alert_story_view, alert_target_set, alert_advice, alert_drop_seen, alert_quick_watch, alert_suggest, alert_savings_share, alert_prefs_change, alert_digest_open (P3); share_open|create|action|revoke (P4; share_view is SPA-only); notif_settings_view|category_toggle|quiet_hours_change|cap_change|open (P6); social_profile_view|profile_save|follow|block|feed_view|idea_publish|idea_open|idea_like|idea_save|comment|report, play_state_view|quiz_start|quiz_answer|quiz_done|h2h_create|h2h_open|h2h_result|board_view|challenge_view (P5, all in the registry on main). Props exactly as the Telemetry.md rows; TelemetryPropsTests rejects anything else.
    • Privacy. No location goes to any new endpoint or telemetry. Share defaults stay private. Cached shared cards and downloaded PNGs live in NSTemporaryDirectory()/share-cards and are purged at sign-out and launch.
    • A11y and adaptive. Dynamic Type to AX5 without clipping primary actions, VoiceOver labels on every icon-only control, 44 pt targets, Reduce Motion respected, light default and dark supported, iPad (sheets as popovers or form sheets, two-column lists where it fits). Every network screen has loading, empty, error-with-retry; a 429 shows the backend detail.
    • Per-user local data is cleared by sign-out (the existing session cleaner).
    • Each task: tests first, CI(<Target>Tests) green with 0 swiftlint warnings, snapshots recorded per the iOS plan's convention and each PNG viewed before commit (iPhone light, iPhone dark, hi/de long-string, AX5, iPad where listed), docs touched (docs/Modules.md, Telemetry.md, Localization.md, Privacy-Labels.md, reference/api-contract.md), and MEMORY.md for each ruling.

    R9 No duplicate or rule-breaking local notifications. The server always writes an in-app row, even when quiet hours, caps or categories suppressed the push. So AlertPoller must pass every row through NotificationGate (category enabled, quiet hours via the evaluator, daily_cap for non-price kinds, instant=targets_only) and a held row is scheduled for the window's end; and when server push is live (features.notifications_v2 and push.apns and a registered device) the local TripReminderScheduler drops its T-7, T-1 and morning reminders (keeps checkout) and the poller drops to the T48 safety net the T33 poller and reminders predate categories; without this a phone buzzes at 03:00 or twice wrong silence or double buzz
    R10 "Near you" is built on-device from GET /notifications/catalog?locale= (nearby_arrival, cached per locale in Caches, bundled English fallback in mobile) plus the existing POST /nearby call. When-in-use permission only: it is evaluated when the scene becomes active during an active trip phase (no Always permission, no geofencing, no background location), at most one per ~500 m cell per 6 h, never inside local quiet hours, only when the nearby switch is on, shown as a local notification (foreground banner). No coordinates in any new call or telemetry iOS cannot do background proximity with when-in-use; honest and privacy-first fewer triggers than Android
