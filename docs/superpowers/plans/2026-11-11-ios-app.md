# Voyager iOS app (spec Phase 7) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native SwiftUI iPhone + iPad app in `rupakc/travel-planner-ios` with parity to today's web app and the
Android app (sign-in, onboarding, search in all modes, streamed results, My Plan, chat, alerts, near me, share viewer,
settings, admin). Built, linted and tested only on GitHub Actions macOS runners. Phase 1 account features plug in
later through seams that exist from day one.

**Architecture:** An XcodeGen-generated app target (`project.yml`, no hand-edited `.xcodeproj`) over one local Swift
package, `Packages/VoyagerKit`, with one target per core layer and per feature module. Every target, test target and
its dependency edges are declared in `Package.swift` by Task 1, so later tasks only add files inside their own
target directories and can run concurrently. Colours, strings and the telemetry registry are vendored from the
`travel-planner` repo at one pinned commit (`upstream.lock`) and turned into an asset catalog, String Catalogs and a
parity fixture by Python generators, so the web stays the single source. Networking is `URLSession` + async/await.
SSE is read with `URLSession.bytes` and parsed off the main actor. State is Observation (`@Observable`) and tokens
live in the Keychain. Every screen reads an injected `AppEnvironment` whose dependencies are protocols, with fakes for
tests and previews.

**Tech Stack:** Swift 6 (language mode 6, strict concurrency), SwiftUI, Observation, iOS 17.0 deployment target,
Xcode 26.0.1 on `macos-15` runners, XcodeGen 2.43.0, SwiftLint 0.59.1, swift-snapshot-testing 1.18.3 (test-only, the
only third-party package), Swift Testing for unit tests, XCUITest for UI smoke, MapKit, AuthenticationServices,
UserNotifications, BackgroundTasks. Python 3.12 (stdlib only) for generators and the stub backend.

**Spec:** `docs/superpowers/specs/2026-11-10-voyager-reimagined-design.md` (§10 iOS, §4 accounts, §7 notifications,
§8 telemetry, §9 design and i18n, §2 store rules). Contracts: `docs/API-Reference.md`, `docs/Telemetry.md`,
`docs/Internationalization.md`, `docs/Theming.md`, `docs/Feature-Parity.md`, `frontend/design/tokens.json`,
`frontend/src/i18n/locales/`. Parity reference: `~/travel-planner-android` (README, its spec
`docs/superpowers/specs/2026-11-05-android-app-design.md`, `docs/reference/api-contract.md`,
`docs/reference/web-ui-inventory.md`, `docs/Networking-and-SSE.md`, `docs/Onboarding-and-Traveller-Types.md`).

**Owner decision (2026-11-11):** Phase 7 starts now, in parallel with Phase 1. Everything that needs Phase 1's API
(sign-up, verification, reset, OAuth, Sign in with Apple, refresh tokens, account deletion) is in Wave 6. Wave 6
starts only after the Phase 1 API contract is merged in `travel-planner`.

## Global Constraints

- Repo `rupakc/travel-planner-ios`, public, MIT. Git identity `rupakc` (noreply). The controller creates the repo. Tasks work on branches and the controller merges.
- iOS **17.0** deployment target, iPhone and iPad (`TARGETED_DEVICE_FAMILY = 1,2`), all iPad orientations, multitasking (Split View, Slide Over, Stage Manager) supported.
- Swift 6 language mode with complete strict concurrency in every target, and zero warnings. The app target sets `SWIFT_TREAT_WARNINGS_AS_ERRORS = YES`. Package targets cannot use unsafe flags, so `scripts/ci/test-unit.sh` fails when the build log has a `warning:` from a file under `Packages/VoyagerKit/Sources` or `App`.
- No Xcode locally. Every build, test and lint runs on GitHub Actions `macos-15`. Python tooling also runs locally (`python3 -m pytest -q tools/tests`). No `.xcodeproj`/`.xcworkspace` is committed (`.gitignore` has `*.xcodeproj`, `*.xcworkspace` except the package's implicit one).
- Pins: every action is pinned by commit SHA, using the SHAs the main repo already uses (checkout `11d5960a326750d5838078e36cf38b85af677262` v4.4.0, upload-artifact `ea165f8d65b6e75b540449e92b4886f43607fa02` v4.6.2, download-artifact `d3f86a106a0bac45b974a628896c90dbdf5c8093` v4.3.0, setup-python `a26af69be951a213d495a4c3e4e4022e16d87065` v5.6.0, cache `0057852bfaa89a56745cba8c7296529d2fc39830` v4.3.0, setup-node `49933ea5288caeca8642d1e84afbd3f7d6820020` v4.4.0). Tools pinned in `tools.lock` (version + SHA-256 of the downloaded archive). A new pin must be a release at least 14 days old on the day it is added.
- Third-party code: only `swift-snapshot-testing` (test targets only). No Firebase, no Alamofire, no analytics SDK (spec §10: direct APNs, no Firebase on iOS).
- Two-way compatibility (CLAUDE.md, spec §2): the app feature-detects every endpoint newer than today's API. `GET /api/config`, `GET /api/auth/providers`, `/api/telemetry` and `POST /api/devices` with `platform: "ios"` may answer `404`/`422`. Each one degrades silently to "off" for the session, with no retry storm and no error UI.
- Theme: `light` is the default. Options `system` / `light` / `dark`, stored in `UserDefaults` key `tp_theme` (same key name as the web). Colours come only from generated tokens (SwiftLint custom rule `no_raw_color` bans `Color(red:`, `Color(#colorLiteral`, `UIColor(red:` outside `Sources/DesignSystem/Generated/`).
- Languages `en`, `es`, `de`, `fr`, `hi`, `zh` (bundle `zh-Hans`), `bn`, with `en` as fallback. The language picker lists native names in web order: English, Español, Deutsch, Français, हिन्दी, 中文（简体）, বাংলা. Stored in `UserDefaults` `tp_lang`. Brand names (Voyager, Apple, Google, Facebook, GitHub), IATA codes, currency codes, place names and backend data are never translated. User-facing text in feature targets only goes through `L10n` (SwiftLint custom rule `no_literal_text` bans `Text("` with a literal outside `#Preview` and test targets).
- AI calls send `locale` (base language code) exactly like the web's `localeField()`: on `/api/search`, `/chat`, `/discover`, `/compare/destination`, `/stress-test`, every single-agent and `/filtered` route.
- Telemetry follows `docs/Telemetry.md` exactly, with `platform: "ios"`. It uses only events and props in the vendored registry. It never blocks: no `await` on a user path, and every entry point is non-throwing and synchronous for the caller. No free text, location, email or name ever goes into props.
- Honesty rules carry over unchanged: estimates are labelled, verification chips are shown as the backend sends them, static-first data stays when the AI fails, and "Book" always means "open the provider page" (`SFSafariViewController`). No in-app payments.
- Performance budget (spec §10): cold start < 400 ms to first frame on iPhone XS; 60/120 fps scrolling; `LazyVStack`/`List` with stable ids; remote images downsampled with ImageIO; no JSON decoding or SSE parsing on the main actor; nothing but first-frame work before the first frame.
- Accessibility: Dynamic Type up to AX5 without truncating primary actions, VoiceOver labels on every icon-only control, 44 pt targets, Reduce Motion respected, AA contrast in both themes (tokens are already contrast-tested on web).
- App Store rules that shape the design (spec §2): in-app account deletion (5.1.1(v)) and Sign in with Apple next to other social logins (4.8) ship in Wave 6 before any App Store submission. UGC report/block/filter (1.2) comes with Phase 5 social, not this plan.
- Bundle id `io.github.rupakc.travelplanner` (same as Android), display name "Voyager", URL scheme `voyager`. Base URL from the build setting `VOYAGER_BASE_URL` (Debug `http://127.0.0.1:8001`, Release `$(VOYAGER_PROD_BASE_URL)`, which CI fills from the repo variable `VOYAGER_PROD_BASE_URL` and which is empty until the owner sets it). The trusted-host list is `VOYAGER_TRUSTED_HOSTS` (space-separated), the one setting that also feeds associated domains (spec §2a).

### Verification convention (used by every task)

- `CI(<filter>)` means: push the task branch, then
  `gh workflow run ios-ci.yml --ref <branch> -f only_testing=<filter> && gh run watch --exit-status`.
  `only_testing` takes `xcodebuild -only-testing:` values (`DomainTests`, `DomainTests/ItineraryLayoutTests`). An empty
  value runs everything. Pass = the run is green, and the "Test summary" step lists the named suites with 0 failures.
  The failing-test step and the passing step are each one CI round-trip.
- `CI(full)` = a push without the input: all jobs (`tools`, `lint`, `unit` × iPhone/iPad, `ui-smoke` × iPhone/iPad, `sim-build`).
- `PY(<path>)` = `python3 -m pytest -q <path>` locally (and in the `tools` CI job).
- Snapshot tests are recorded on CI: `gh workflow run ios-ci.yml --ref <branch> -f only_testing=<suite> -f record_snapshots=true`,
  then `gh run download <id> -n snapshots -D Packages/VoyagerKit/Tests` and commit the PNGs. After that, re-run without
  recording and expect it green. Review each recorded PNG (Read tool) before committing it.

## Review Focus

1. **The app goes to the background mid-stream** (lock the phone during a 60 s search, or a Slide Over resize while the itinerary streams): on return the search resumes by retrying once and replaying into the sections already shown. You get no duplicated sections and no lost static data, and `search_abandon` is not sent for a stream that finished. → `ResultsModelTests.test_interruptedStreamRetriesOnceAndKeepsSections` + `test_modelSurvivesViewRebuild` in Task 24.
2. **An older or partial backend** (`/api/config` 404, `/api/auth/providers` 404, `/api/telemetry` 404, `POST /api/devices` 422 for `ios`, `/api/notifications` 404): the app works, every social button shows the "coming soon" note, telemetry turns itself off for the session after one request, and nothing loops. → tests in Tasks 5, 6, 7, 33.
3. **Stale and expired sessions** (the 24 h JWT expires while backgrounded; a late 401 arrives for the previous token after a fresh login; a reinstall leaves a Keychain item behind): only a 401 for the *current* token signs the user out, with the "session expired" message. A reinstall starts signed out. → `AuthStateTests` in Task 7 and `APIClientTests.test_staleUnauthorizedIgnored` in Task 5.
4. **Long strings and other scripts** (German and French labels, Hindi/Bengali/Chinese glyphs, AX5 Dynamic Type, an iPhone SE width, iPad Split View at 1/3 width): nothing clips a primary action, and a missing translation shows English, never the raw key. → generator test `test_missing_key_falls_back_to_english` (Task 3), `SharedUISnapshotTests` (Task 13), the audit snapshots in Task 40.
5. **Telemetry leaking user content** (a `tid` built from a plan name, a route with a share token, a burst of 1 000 taps, the disk full): ids failing the token rule are dropped on the device, routes are templates, the queue is capped at 500, and a write failure never surfaces. → `TelemetryPropsTests`, `TelemetryQueueTests` in Task 6.
