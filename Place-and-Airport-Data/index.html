    Place and Airport Data

    Travel Planner turns whatever the user types ("Milano", "Portland, ME", "Zermatt") into airport codes for live flight search, and offers an airport-and-place typeahead. Both run against open data committed to the repo and seeded into SQLite. No web call is involved, except for one narrow case described under Bare airport codes.

    Sources and licences

    Attribution: Contains data from GeoNames (geonames.org), CC BY 4.0. The GeoNames data has been modified (filtered, name-folded, scored and linked to airports; country names, non-town features and districts extracted; a suburb flag derived), and GeoNames does not endorse these changes.     Regenerating the data

    backend/scripts/build_place_data.py is standard-library only and deterministic (sorted rows, gzip mtime 0); it takes about a minute and treats the downloaded sources as untrusted input. Download the OurAirports CSVs and GeoNames cities1000.zip / admin1CodesASCII.txt / allCountries.zip (423 MB, streamed, not unzipped) into a directory of their own, then from the repo root:

    python3 -I backend/scripts/build_place_data.py \
    --ourairports /path/to/ourairports-src \
    --geonames-cities /path/to/geonames-src/extracted/cities1000.txt \
    --geonames-admin1 /path/to/geonames-src/admin1CodesASCII.txt \
    --geonames-all /path/to/geonames-src/allCountries.zip \
    --out backend/app/db/data > conflicts.txt

    The script writes airports.csv, places.csv.gz, admin1.csv, countries.csv and features.csv.gz, and prints a summary and a conflict report to stdout (not committed). Then run python3 -m pytest tests/test_build_place_data.py from backend/, update the snapshot date in the data README, and commit the five files. The data README holds the derivation rules, including the notability threshold calibration for features. hints.json is edited by hand.

    Versioned seeding

    At startup, seed() in backend/app/db/seed_airports.py loads the files into the airports, places, place_names, features, feature_names and admin1 tables of $DATA_DIR/airports.db. feature_names holds each feature's name, its ASCII spelling and both without a generic part ("Kakadu National Park" → "kakadu", "Mount Everest" → "everest") as tier 0, and its alternate names as tier 1.

    • The data version is the sha256 of a loader tag (place-data-loader:3) plus the bytes of airports.csv, places.csv.gz, admin1.csv and features.csv.gz, truncated to 16 hex characters and stored as meta.place_data_version. An older places table gains its satellite column in place.
    • If the stored version matches, seeding is skipped (about 5 ms).
    • Otherwise one BEGIN IMMEDIATE transaction (waiting up to 30 s for another worker's lock) upserts the airports, sets scheduled = 0 on old rows missing from the dataset, and rebuilds places, place names and divisions with their indexes. On an empty database this takes about 2.5 s and produces about 316,000 place-name rows, 113,000 feature-name rows and a database of about 33 MB.
    • Backups leave these tables and the version out, so a restored database reseeds them.

    It can also be run by hand: cd backend && python -m app.db.seed_airports. After seeding, places_db.warm() builds an in-memory airport-name index (about 0.06 s).

    How a typed place resolves

    lookup_city_iata(text) (backend/app/db/database.py) returns up to 3 comma-joined scheduled airport codes, best first, or None. The request validator (backend/app/schemas/request.py) uses it to fill origin_iata and destination_iata for flight search, the fare calendar and Compare. When it returns None, flights fall back to AI estimates for that route.

    The rules, in order

    1. An airport code. An upper-case three-letter code is used as typed, after mapping retired codes ("LHR" → LHR, "PNH" → KTI). Lower-case text tries places first and falls back to the code only if it is a scheduled airport ("lhr" → LHR).
    2. A typeahead label such as "LGW — London, United Kingdom" uses its code alone.
    3. A curated hint: an island, destination or region from hints.json, unless a stated country contradicts it.
    4. The curated city list: airports whose served city matches the text (accent-folded, with St/Saint variants and city aliases), restricted by any stated country, ISO code, alias or region code. A city name that is ambiguous or contested gives None.
    5. GeoNames place resolution (resolve_place, backend/app/db/places_db.py):
    6. Candidates are places whose own name matches. Alternate names count only when no place has that own name, or when the own-name places are small (under 20k) and the alternate one is at least 10× bigger and 150k or more.
    7. Exonyms from hints.json map an English name to a specific place, or mark it ambiguous.
    8. A country typed alone gives its top place; a first-level division ("Florida", "Scotland") joins as its top place unless a town of that name is comparably notable. Country names include the native and other-language names in countries.csv ("Deutschland" → BER, "Nippon" → HND); a name that is also the own name of a town of 15k or more stays the town's ("Columbia", South Carolina), unless it is the country's own name, curated as an alias ("Nederland" → AMS, not Nederland, Texas).
    9. Country names that are also a town's own name ("Eretria", "Coria", "Grenade") name the country only as a qualifier; typed alone they stay the town.
    10. Stated qualifiers (country name in any of those forms, ISO code, alias, a qualifier-only alias such as KSA, US/CA/AU/BR/IN region code or a division name) filter the candidates ("Berlin, Deutschland", "Riyadh, KSA"). A qualifier that contradicts every candidate gives None.
    11. An airport whose whole name equals the text can win ("Wagga Wagga" → WGA), but never over a place of 40k or more.
    12. Suburbs yield to towns with their own airport. When the top candidate is a satellite and the best candidate whose first airport is its own scores at least 1/10 of it, the satellites scoring above that town drop out ("Peoria" → PIA, Illinois, not the Phoenix suburb).
    13. A namesake with its own named airport. When the top candidate would win without an airport named for it, and one comparable namesake (score within 5×, at least a third of the people) flies from its own named airport, that namesake leads if the top's nearest airport is over 75 km away ("Tongren" → TEN, Guizhou); otherwise the name is ambiguous ("Salisbury").
    14. The winner must score 3× the next candidate (score = population × notability). A place under 15k wins only alone or through a hint; one under 5k with no airport within 100 km gives None.
    15. Non-town features. When no candidate is a town of 15k or more (and no division or curated city has the name), a notable feature by that name answers with its airports ("Kakadu" → DRW; "Arches" → the national park's CNY, not the French village), unless a town of that name lies within 50 km of it (Paros, Naxos: the island town and its airport). Of several features, the most notable needs 3× the next one's notability; otherwise the answer is None, even when small towns share the name ("Mount Olympus": Cyprus or Greece). Districts answer the same way ("Ealing" → LHR, "Manly" → SYD), except by a contested name that many sections elsewhere share: then the answer is None, never another town ("Centar", "Chinatown", "Downtown"). An alternate-name town of 15k or more with at least twice the best feature's alternate names blocks the feature path and competes ("Vila" → Port Vila's VLI, not an Albanian peak); one known only by its people (not by alternate names) must have 3× the people of every town of that name, alternate names included ("Legazpi" stays the Philippine city).
    16. The place's linked airports are returned. With a curated city in the same country they are appended to the curated codes ("New York" → JFK, LGA, EWR); otherwise foreign airports are dropped unless the place has no domestic one.
    17. Last resort: dataset airports whose display city matches.

    Text without a comma is also tried as "City, Qualifier" when the last words name a country or region ("Chicago IL", "Berlin Germany"). Generic affixes are retried too ("Zanzibar Island", "Banff National Park", "Tokyo city").

    Suburbs (satellite places)

    A place is a satellite when its first airport is not named for it but for a place scoring at least 10× more within 60 km: Peoria, Arizona flies from Phoenix's PHX, while Peoria, Illinois has PIA. "Named" is core.places.is_named_airport: the airport's display city is the place or its name names the place, never distance alone. A deep suburb (owner ≥ 100× bigger) drops out when a namesake that is an ordinary satellite or flies from its named airport scores more ("Pontevedra" → Spain's SCQ, VGO, not the Buenos Aires suburb). A satellite that would win yields to a namesake with its named airport scoring ≥ 1/10 of it ("Peoria" → PIA); comparable namesakes stay ambiguous ("Redmond", "Darien"). Two comparable suburbs stay ambiguous ("Glendale": California and Arizona → None), and a satellite keeps its lead over a far smaller namesake.

    Non-town features

    features.csv.gz holds 31,995 GeoNames features that are not towns: islands, archipelagos and atolls, peninsulas, parks and reserves, resorts, regions and coasts, mountains, ranges, peaks and volcanoes, valleys, lakes, beaches, ancient and historical sites, ruins and monuments, deserts, gorges and canyons, glaciers, capes, fjords and caves, plus 7,306 famous districts that take their city's airports (Ealing, Manly, Frankston, Shinjuku). Only notable ones are kept: at least 10 GeoNames alternate names (5 for parks, reserves, resorts, glaciers, capes, fjords, caves, islands and deserts; such a weakly notable island or desert is dropped when another GeoNames row has its name), and an airport. Names also match without generic words in several languages ("Isola Stromboli" → "stromboli", "Parque Nacional de Doñana" → "donana", "Killington Peak", "Annapurna I"); after an island, park or peninsula affix only a feature of that kind answers ("San Blas Islands" is not Argentina's San Blas). Their airports are those on the island (for islands), then large and medium airports within 250 km, same country first, by distance with a large airport counted at half its distance (Florida Keys → EYW, then MIA; Lake Tahoe → RNO before Truckee). The data README has the calibration (5 → 83k features and 3.6 MB; 10 → 14k and 0.9 MB; 20 → 1.3k).

    Curated hints still come first; features answer names the hints do not cover ("Grand Teton" → JAC, "Crater Lake" → MFR, "Mount Rushmore" → RAP, "Tikal" → FRS, "Haida Gwaii" → YZP). Vast regions give a single point, so their airports can be rough (Sumatra → PKU, Pekanbaru); big islands with several gateways are curated ("Borneo" → BKI, KCH).

    Bare airport codes

    The one web path: when a request's origin or destination is a bare 3-letter code that is not in the database or REPLACED_CODES, lookup_iata runs a DuckDuckGo search plus a Haiku extraction to name the city, and stores the answer (backend/app/db/database.py). Everything else is local.

    Folding and shared rules

    app.core.places.fold_place (accent and case folding) is shared by the generator and the runtime, so names match the same way in both. backend/app/core/places.py also loads hints.json and defines OWN_AIRPORT_KM = 25 and NEVER_LINK = {"ECN"} (Ercan is never suggested for a place, only when typed). Region code tables for the US, Canada, Australia, Brazil and India live in backend/app/db/airport_regions.py.

    Autocomplete

    GET /api/airports/search?q=&limit= (search_airports in backend/app/db/database.py; default 10 results, at most 50):

    • Matches airports by code, city, airport name or country, plus the airports of GeoNames places and curated hints whose folded name starts with the query ("kyoto" → ITM, KIX, …; "milan" → MXP, LIN, BGY).
    • From the fourth letter, when no town of 15k or more and no curated hint matches, up to 3 notable features whose name starts with the query add their airports, below every town match ("kakadu" → DRW, MNG).
    • A country's other name or alias suggests the airports of the place the resolver picks for it, and keeps namesakes abroad out ("deutschland" → BER, not Deutschlandsberg's GRZ; "nederland" → AMS, RTM). From five letters, a prefix of one country's other names suggests that gateway first (a GeoNames other-language name yields to a town or district whose own name starts so: "jordaa" → Amsterdam's Jordaan, not Jordan) and still lists the towns ("deuts" → BER, then GRZ). Official names still match the airports' country column ("germany" lists German airports).
    • The suburb rule applies to every matched name: a satellite the resolver sets aside ranks just below its namesake, and stays listed ("peori" → PIA, PHX; "pontevedra" → SCQ, EZE, VGO, AEP).
    • Features also match by alternate and short names ("sifnos" → JTR).
    • When the whole query (four letters or more) resolves by its own name to a town of 15k or more, or to a curated hint, feature or district while no real town's name starts so, lookup_city_iata's answer leads the list ("ealing" → LHR before Ealing, New Zealand's TIU; "peoria" → PIA).
    • Alternate names count for places of 100k or more from the fourth letter ("münch" → München).
    • A place contributes only its own-country airports, and only places scoring at least 1/10 of the best match count.
    • Order: exact code, code prefix, exact name, name prefix, then the rest. Lower-case three-letter text that names a place lists the place first ("hue" → HUI; "HUE" → HUE). Within a class, the more notable place comes first, then curated order, then the bigger airport.
    • "Contains" matches are dropped once there are real matches, and unscheduled airports appear only for their exact code.

    Each row has iata_code, name, city, country, country_code.

    Quality

    • Golden set. backend/tests/data/golden_places.csv has 736 cases (443 resolution, 275 data, 18 autocomplete; 578 "first code matches", 98 exact, 50 subset and 10 expected None). tests/test_golden_places_runtime.py runs them all and forbids web calls.
    • Fresh blind probe. On inputs not used during development, about 1.7% resolved to a wrong airport. More inputs now resolve to None by design: when a name is genuinely ambiguous, no answer (and an AI-estimated fare) is better than a confident wrong airport.
    • Country names, suburbs and features (2026-10-30). Measured on the five earlier probe sets (2,484 inputs) and a fresh blind set of 451: on the earlier sets no input gained a wrong airport and one was fixed (Peoria); on the fresh set the 8 wrong answers (7 also on main) were fixed. These figures hold for those sets only.
    • Speed. lookup_city_iata takes about 0.8 ms per call at p50 and under 2.5 ms at p99 (warm), so request handlers call it synchronously.
